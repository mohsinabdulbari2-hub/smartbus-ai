🧠 Problem Statement
What's Wrong
The current crowd load pipeline produces values that cluster in a narrow range, causing one of two failure modes:
"All Moderate" clustering — Nearly every bus shows "Moderate" because load values hover around 0.35–0.65 with no spread into low or high tiers
"All Crowded" clustering — Load values run too hot, pushing almost every bus into high or very_high, making the UI feel broken and untrustworthy
Both failure modes destroy rider trust. If every bus is always "Crowded," the label becomes meaningless noise.
What Good Looks Like
Real Bangalore bus ridership is heterogeneous. At any given moment on any given route, you'd expect a natural spread: some near-empty buses (just departed a terminus, off-peak route, contra-peak direction), some moderately full buses, some crowded ones, and occasionally a standing-room-only bus during peak crush. The fix must reproduce this spread statistically — not perfectly per bus, but correctly across the fleet.
What This Fix Is NOT
Not a logic rewrite
Not a new data model
Not a new API integration
Not a UI redesign
This is pure distribution tuning — adjusting the stochastic parameters of the existing load calculation to produce a realistic spread. Think of it as calibrating a probability distribution, not building a new system.
